Proposed Cloud principles

  • Your edge remains authoritative. Hosted policy can narrow what a connector allows, not grant something its local policy denies.
  • No long-lived Tailscale OAuth secret in TetherBound Cloud. Tailnet enrollment happens at the customer edge.
  • No direct inbound cloud path into the tailnet. The edge opens an outbound authenticated session to the hosted relay.
  • Raw host output is not retained by default. Results are streamed to the MCP response while audit records retain operational metadata.
  • Open edge. The connector, agent, protocol, local policy, and platform adapters remain inspectable and self-hostable.
  • Read-only first. Any future write action gets its own typed capability and prepare → approve → execute flow.

Who we want to test with

We are especially interested in people who operate a small but real private fleet: homelabs, VPSs, self-hosted services, remote development machines, agency/client environments, GPU boxes, or small production infrastructure.

Mixed fleets are particularly useful. The roadmap is designed around Linux through Tailscale SSH plus a native outbound agent for Windows and macOS.

What we want to learn

  • Which infrastructure questions would you actually ask an AI assistant every week?
  • What is the most privileged read capability you would feel comfortable granting?
  • Would you install a small open-source agent on Windows or macOS to avoid passwords and unrestricted remoting?
  • Which pieces of the current DIY setup would make you choose a hosted service instead?
  • Which actions, if any, would you eventually allow after a separate approval?
  • What data-retention and audit guarantees would you need for production systems?
