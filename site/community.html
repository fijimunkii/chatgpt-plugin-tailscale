Roadmap

Cross-platform agents

Windows and macOS targets will use a native outbound TetherBound Agent while preserving the same normalized MCP tools and local policy model.

What ships in the current proof of concept

  • An embedded tsnet Tailscale identity.
  • Independent local host filtering by exact tag and/or host selector.
  • Strict SSH host-key verification against Tailscale-distributed keys.
  • Tailscale SSH authentication without a stored SSH private key.
  • Seven fixed read-only MCP tools: host listing, host inspection, system summary, disk usage, process list, service status, and service logs.
  • Exact service allowlists, timeouts, line limits, row limits, and output byte limits.
  • An idempotent bootstrap that walks through Tailscale policy, target setup, gateway enrollment, Secure MCP Tunnel, and local process startup.
  • A distroless non-root container image and CI coverage.

Quick start

The current setup still requires administrator steps in both Tailscale and OpenAI. The bootstrap codifies those steps and preserves existing configuration when rerun.

git clone https://github.com/fijimunkii/chatgpt-plugin-tailscale.git
cd chatgpt-plugin-tailscale
./bootstrap

For the current pull request implementation, check out agent/initial-tailscale-mcp-gateway first. After setup, launch the local gateway and tunnel together with:

make up

What stays open

The roadmap treats the customer-side security boundary as open infrastructure. The gateway/edge connector, host agent, protocol, native adapters, local policy engine, and Community setup path are intended to remain reviewable and self-hostable.

What Cloud adds

Cloud is not intended to remove the local boundary. It is intended to remove operational friction: hosted authentication, a stable public MCP endpoint, connector lifecycle, centralized policy, health, and audit metadata. The customer edge still holds the tailnet identity and still performs the final local authorization decision.
